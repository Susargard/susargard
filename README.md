# susargard — сайт Арины Смирновой

Портфолио-сайт: графика, иллюстрация и реставрация. Статический сайт на Astro,
контент лежит в Git, редактируется через админку Sveltia CMS. Хостинг — GitHub
Pages, без платных сервисов, аналитики и форм.

Адрес: **https://susargard.github.io/susargard/**

## Что внутри

- три раздела: «Графика», «Иллюстрация», «Реставрация»;
- главная с избранными работами и пустыми состояниями;
- страницы работ: обложка, описание, галерея с лайтбоксом, детали, файлы,
  сравнение «до / после» для реставрации;
- страницы «Обо мне» (главный блок — опыт) и «Контакты»;
- тёмная/светлая типографика, шесть цветовых тем, фоновые изображения и декор;
- админка на русском: `/admin/`;
- автоматическая сборка и публикация через GitHub Actions.

## Локальный запуск

Нужен Node.js **22.23.4 или новее** (в проекте есть `.nvmrc`).

```bash
nvm use
npm install
npm run dev
```

Сайт откроется на `http://localhost:4321/susargard/`.

Полезные команды:

```bash
npm run dev        # локальная разработка, черновики видны
npm run build      # продакшен-сборка, черновики скрыты
npm run build:demo # сборка с демо-проектами (PUBLIC_SHOW_DRAFTS=true)
npm run preview    # посмотреть собранный сайт
```

Демо-проекты лежат в `src/content/projects/demo-*` и помечены `draft: true`.
В обычной сборке и на сайте они не показываются. Чтобы посмотреть их локально,
достаточно `npm run dev`; чтобы собрать демо-версию — `npm run build:demo`.

## Как добавить работу

1. Откройте **https://susargard.github.io/susargard/admin/**.
2. Войдите через **Sign In Using Access Token** (токен создаётся на GitHub:
   Settings → Developer settings → Personal access tokens → Fine-grained tokens,
   доступ к репозиторию `Susargard/susargard`, права **Contents: Read and write**).
3. «Проекты» → «Добавить проект».
4. Заполните:
   - **Название**;
   - **Раздел** — Графика / Иллюстрация / Реставрация;
   - **Краткое описание** — 1–2 предложения для карточки;
   - **Год**, **Избранное на главной**, **Порядок**;
   - **Обложку** и её описание;
   - **Галерею** — 10–30 изображений, у каждого обязательно описание;
   - при необходимости — **Детали**, **Теги**, **До / после**, **Файлы**, **Оформление**;
   - **Полное описание** — свободный текст.
5. Оставьте **Черновик** включённым, пока работа не готова. Когда всё проверено,
   выключите его и нажмите «Опубликовать».
6. Подождите 1–2 минуты: GitHub Actions пересоберёт сайт.

### Картинки

- Формат: JPG, PNG или WebP. Админка сама пережмёт растровые изображения в WebP
  (до 2560 px по длинной стороне, качество 85).
- Ориентир: 1600–2560 px по длинной стороне, 10–30 изображений на проект.
- Один файл — до 50 МБ. Git LFS не используется.
- Для обложки лучше вертикальный или горизонтальный кадр с запасом по краям:
  на карточках он кадрируется.
- Не удаляйте изображения из репозитория вручную: удаляйте их через админку или
  заменяйте в проекте.

### Файлы

PDF, DOCX, ZIP и другие документы можно приложить к проекту в блоке **Файлы**.
Они сохраняются в `public/files/<адрес-проекта>/`. Если файл больше 50 МБ,
загрузите его на внешний диск и укажите ссылку в поле **Внешняя ссылка**.

## Как редактировать остальное

- **Разделы** — названия, короткие описания, обложки, темы и декор.
- **Страницы → Обо мне** — вступление, опыт, образование, услуги, выставки,
  портрет и свободный текст.
- **Страницы → Контакты** — заголовок и вступление.
- **Настройки сайта** — имя, псевдоним, роль, город, контакты, статус заказов,
  тексты главной, портрет, подпись в подвале и SEO-описание.

Пустые контакты не выводятся: если почта или Telegram не заполнены, ссылок на
них не будет. Instagram уже указан.

## Темы и оформление

Доступны темы: «Бумага», «Шалфей», «Терракота», «Камень», «Глина», «Тёмная».
Их можно задать у раздела и у отдельного проекта. Дополнительно настраиваются:

- цвет фона и фоновое изображение;
- затемнение фона (если текст плохо читается);
- светлый или тёмный текст;
- акцентный цвет;
- декоративное изображение, его положение, размер и прозрачность.

Если у проекта ничего не задано, он наследует оформление раздела.

## Публикация

Репозиторий: `git@github.com:Susargard/susargard.git`, ветка `main`.

```bash
git add .
git commit -m "Обновление сайта"
git push origin main
```

После пуша workflow `.github/workflows/deploy.yml` собирает сайт и публикует его
на GitHub Pages. В настройках репозитория должен быть выбран источник
**Settings → Pages → Build and deployment → GitHub Actions**.

Первый запуск:

1. убедиться, что репозиторий публичный (иначе GitHub Pages на бесплатном плане
   не работает);
2. выбрать источник GitHub Actions;
3. дождаться зелёной галочки в Actions;
4. открыть `https://susargard.github.io/susargard/`.

## Резервная копия

Весь сайт — это репозиторий. Достаточно периодически скачивать его архив
(GitHub → Code → Download ZIP) или держать локальную копию. Медиафайлы лежат
в `src/content/projects/...` и `public/files/...`.

## Если появится свой домен

1. В `astro.config.mjs` заменить:
   ```js
   site: 'https://example.ru',
   base: '/',
   ```
2. Добавить файл `public/CNAME` с доменом.
3. Обновить абсолютные адреса в `public/admin/config.yml` (`site_url`,
   `display_url`, `logo_url`, `public_folder` для файлов и изображений сайта),
   `public/robots.txt` и `src/content/settings/site.yaml` (`ogImage`).
4. Проверить, что все ссылки и админка открываются по новому адресу.

## Структура

```text
src/
  content/
    projects/       работы: index.md + изображения
    sections/       три раздела
    pages/          «Обо мне» и «Контакты»
    settings/       настройки сайта
  components/       карточки, галерея, до/после, файлы, декор
  layouts/          общий каркас и SEO
  lib/              темы, ссылки, плюрализация, контакты
  pages/            маршруты
  styles/           дизайн-система
public/
  admin/            Sveltia CMS
  files/            документы проектов
  images/site/      OG-картинка и изображения сайта
scripts/            генератор демо-изображений
```

## Технические заметки

- `astro.config.mjs`: `site` и `base` для project site на GitHub Pages.
- Внутренние ссылки собираются через `withBase()` из `src/lib/content.ts`.
- Черновики: `draft: true`; в dev видны, в продакшене — нет.
- Sveltia CMS закреплена в `package.json` и лежит локально в
  `public/admin/sveltia-cms.js`, внешний CDN не нужен.
- `npm run check` (astro check) на некоторых машинах падает с нехваткой памяти
  из-за известной проблемы `@astrojs/check`; для проверки используйте
  `npm run build`.
- Права на реставрационные объекты и фотографии — зона ответственности автора.
  Если у проекта есть ограничения, их можно указать в поле **Кредит**.
